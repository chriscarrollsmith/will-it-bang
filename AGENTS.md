## Will it bang?

The objective of this project is to predict a Tweet's engagement based only on past/current information available from the Twitter Community Archive API.

The rules:

- You may use or fine-tune any MIT-licensed model, as long as it can (safely) be self-hosted or used through a free API.
- Alternatively, you may train your own model.
- Modal is installed in this project, and you have $30 in credits.
- Optionally, you may train and run locally on this consumer laptop.
- You may experiment with different ways of constructing input features, but all input-output pairs must use the same programmatic approach, and it is critically important to avoid future information leakage.

Safer LM labels are descriptive and time-invariant enough in principle (e.g. sentiment, gender presentation, humor/controversy tags of the *text*).

Media types (`photo` / `video` / `animated_gif`) cached in `~/.cache/will-it-bang/media_cache.parquet`; train with `--media-types` (opt-in).

- Optional train-fit TF-IDF→SVD on `full_text` (default 128 dims) adds a small honest lift once fav/RT history is banned.
- Denser leakage-safe popularity: scan full dump for replies/quotes to all tweets by sampled `account_id`s (`reply_to_tweet_id` / `quoted_tweet_id` / `reply_to_user_id` with `created_at < T`); when `reply_to_user_id` is null, coalesce from parent `account_id` if the parent tweet is in the dump (stream-era repair in `load_author_graph`). - Provenance columns: `archive_upload_id` + `is_stream` (null upload id ⇒ browser-extension stream) are carried into `dataset.parquet` / val preds; `analyze.py` slices locked wa_* by upload vs stream (joins dump if preds lack the column). Patch an existing dataset with `uv run prepare.py --provenance-only`.
- Rebuild features with `uv run prepare.py --skip-media` to reuse media flags from an existing `dataset.parquet` and skip the slow CA attachment API.
- Pre-T author text affinity: mean of prior MiniLM vectors per account, then cosine/L2 vs current tweet (compute before emb PCA so PCA does not wipe the raw space).
- Reply/quote parent context: join `reply_to_tweet_id` / `quoted_tweet_id` from the dump; use parent MiniLM cosine + pre-T reply arrivals on the parent (never parent fav/RT). Prefer reply edge on reply parents and quote edge on quote parents; hop-2 must predate hop-1 and child; features include child/hop-2 cos, hop-1/hop-2 cos, pre-T hop-2 replies (never fav/RT).

- **Primary metrics (locked):** within-account Spearman by stratum — `spearman_within_account_nonreply_wmean` and `spearman_within_account_reply_wmean` (draft quality within author; NR and replies ranked separately). Guardrails: global `spearman_nonreply` / `spearman_reply`, rate RMSE, `mean_underpred_nonreply_top10`. Between-author / reply-vs-NR level are secondary calibration signals.

- Default hybrid: `--hybrid-rank` (disable with `--no-hybrid-rank`) fits level loss (default asymmetric) then stratum LambdaRank (NR + reply); blends by keeping per-account level mean/std and imposing ranker within-account order. **v31b:** within-account NR wmean 0.187→0.227, reply 0.172→0.280; global Spearman/RMSE guardrails flat-to-up.
- Hybrid/LambdaRank label mode: `--rank-relevance {dense,extreme}` (default dense 0..n-1 within account). `extreme` maps to 0–4 quantile grades (cuts 50/75/90/95; groups <6 stay dense) to focus the ranker on the viral tail.
- Time regimes: `year` / month seasonality + coarse platform eras from `created_at` (pre-2015, algo timeline, pre-Musk, Musk early/late) — leakage-safe calendar features in `train.py`. Opt-in era priors/heads: `--era-te` / `--era-heads` with `--era-key {platform_era,year}` (LOO mean by key + key×reply; specialist per bucket with `--era-head-min-train` fallback). Prefer `--era-key year` when time-holdout val is musk_late-dominated.
- Default train target is exposure **rate** `log1p(eng/(min(age_days,30)+1))` so the model fits intensity, not dump maturity; evaluate ranking in that space. Dump-total decode is diagnostic only (`rmse_log_raw_dump`). Use `--no-exposure-correct --residual` for the old dump-total objective.
- Train-fold account target encoding: LOO mean of the model target by `account_id`, shrunk to the train global mean (`--account-te`, default on; `--account-te-prior 20`).
- Emb kNN TE (default on): train-fold MiniLM neighbors’ mean/std rate + sim (`--emb-knn-te`, `--emb-knn-k 40`); PCA / affinity must match only `emb_\d+` so `emb_knn_*` survive. Tiny lift in v22b (0.607→0.606).
- Emb engagement CAV (opt-in `--emb-cav`): train-fold unit direction `μ_hot−μ_cold` on raw MiniLM (top/bottom `--emb-cav-quantile`, default non-reply fit); project before emb PCA → `emb_cav_proj` / `_sq`.
- Emb PLS (opt-in `--emb-pls K`): train-fold `PLSRegression` of raw MiniLM→target → `pls_0..K-1` before emb PCA; use `--emb-pca 0` to replace variance PCA. Dense; smoke via train `corr(pls_0,y)`.
- Residual emb CAV (default on after **v47**): OLS-residualize MiniLM vs `account_mean_rate` / `is_reply` / `inbound_replies_per_tweet` then CAV → `res_emb_cav_proj` / `_sq` (`--residual-emb-cav`; `--no-residual-emb-cav` to ablate). Locked scoreboard **v48b** on X-complete full data: wa_nr +0.008 / wa_rp +0.010 / global_nr −0.009 / rmse flat vs same-rebuild control (dump-parent v47 was +0.021 wa_nr). Opt-in residual PLS (`--residual-emb-pls K`) still regresses wa_nr — leave off.
- Error-driven fail clusters (opt-in `--fail-clusters`): 3-fold LGBM OOF without emb (or `--fail-clusters-mode te`); k-means on top under-pred MiniLM (default non-reply); features `fail_min_dist` / `fail_dist_*` before emb PCA.
- Emb cluster TE (opt-in `--emb-cluster-te`): train-fold MiniBatchKMeans on L2 MiniLM (`--emb-cluster-k 32`); LOO shrunk `cluster_mean_rate` + `cluster_min_dist` / crosses vs account & knn TE; fit before emb PCA.
- Default LGBM objective is asymmetric MSE (under-prediction weight 3 via `--loss asymmetric`). Opt-in SERA (`--loss sera`; Ribeiro & Moniz): train-fold adjusted-boxplot + PCHIP φ, weights `floor+(1−floor)·φ` (`--sera-floor 0.05`, high-tail only); `--sera-nonreply-only` fits/applies φ on non-replies only. **v33:** under hybrid, SERA does not move wa_* (ranker dominates); level NR-only SERA regresses wa_nr — stay opt-in for magnitude (RMSE) only. Also: `--loss huber` / `--loss mse` / `--loss quantile`.

## Cursor Cloud specific instructions

- Environment is **CPU-only** (no CUDA). MiniLM embedding in `prepare.py` runs on CPU at ~150 tweets/s; the full `--max-tweets 120000` default therefore takes a while — for a quick sanity run use a small scale, e.g. `uv run prepare.py --max-tweets 6000 --per-account-cap 60 --skip-media`.
- The full `prepare.py` first downloads the ~900MB `enriched_tweets.parquet` dump to `~/.cache/will-it-bang/` (cached across runs; re-fetch with `--force-download`). All artifacts (`dataset.parquet`, `embed_cache.parquet`, `model.txt`, `val_predictions.parquet`, caches) live under `~/.cache/will-it-bang/` and are gitignored.
- Happy path: `uv run prepare.py --skip-media` → `uv run train.py` → optional `uv run analyze.py`. Default prepare already includes inbound mentions (via `load_author_graph`) and provenance (`is_stream`). Use `--mentions-only` / `--provenance-only` only to patch an older `dataset.parquet`.
- `--skip-media` reuses media flags from any existing `dataset.parquet` (0% if none) and skips the slow CA media API — good for cloud runs where the media join dominates wall time.
- There is **no test suite and no configured linter** (nothing in `pyproject.toml`); "running the app" means the `prepare.py` → `train.py` (→ optional `analyze.py`) pipeline. `train.py` on a prepared `dataset.parquet` finishes in seconds.
- Metrics on a small scaled sample will not match the full-scale `experiments.md` numbers (fewer accounts/rows); that is expected — use full scale for real comparisons.

### Shared S3 cache (cross-container)

Cursor cloud containers do not share `~/.cache/will-it-bang/`. Use the triage bucket to hand off prepared artifacts between agents.

- Env (injected into the cloud environment): `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_DEFAULT_REGION`, `AWS_S3_TRIAGE_BUCKET`. Install CLI once if missing: `pip install --user awscli` (or `uv tool install awscli`).
- Layout: `s3://$AWS_S3_TRIAGE_BUCKET/incoming/` is a producer drop zone (variant names OK); `s3://$AWS_S3_TRIAGE_BUCKET/cache/will-it-bang/` is the canonical shared cache mirroring local filenames.
- Share: `dataset.parquet` (and named full-scale variants), `embed_cache.parquet`, graph/parent caches (`mention_`, `x_parent_`, `dyad_`, `media_`, `url_`, `archive_upload_`), `model.txt`, `val_predictions.parquet`, `metrics.json`. Usually skip `enriched_tweets.parquet` (re-fetch from CA). Never upload `.env` or API secrets.
- Helper: `bash scripts/s3_cache_sync.sh {pull|push|pull-incoming|promote-incoming|ls}`.
  - Consumer (cache already promoted): `bash scripts/s3_cache_sync.sh pull` then `uv run train.py` / `uv run analyze.py` (skip `prepare.py` unless feature code changed).
  - Consumer (only `incoming/` populated): `bash scripts/s3_cache_sync.sh pull-incoming` (maps `dataset_xcomplete_full.parquet` → `dataset.parquet` when present).
  - Producer (after a successful full prepare/train): `bash scripts/s3_cache_sync.sh push`.
  - One-time promote drop zone → canonical: `bash scripts/s3_cache_sync.sh promote-incoming`.
